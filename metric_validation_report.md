## 1. Answer Correctness Metric Audit

### 1.1 Formula Specification
Answer Correctness ($C$) is computed as a weighted combination of semantic embedding similarity and lexical keyword token recall:

$$C = \min\left(1.0, \, 0.6 \times S_{\text{semantic}} + 0.4 \times R_{\text{token}}\right)$$

Where:
- $S_{\text{semantic}} = \max\left(0.0, \, \cos(\mathbf{e}_{\text{base}}, \, \mathbf{e}_{\text{rag}})\right)$
- $\mathbf{e}_{\text{base}}, \mathbf{e}_{\text{rag}}$ are dense vector embeddings generated by `SentenceTransformer("all-MiniLM-L6-v2")`.
- $R_{\text{token}} = \frac{|\mathcal{T}_{\text{base}} \cap \mathcal{T}_{\text{rag}}|}{|\mathcal{T}_{\text{base}}|}$, where $\mathcal{T}$ represents unique alphanumeric tokens excluding English stopwords (`{"the", "a", "an", "is", "are", "of", "and", "in", "to", "for", "with"}`).

### 1.2 Mathematical Behavior & Limitations
1. **Recall-Only Token Metric:** $R_{\text{token}}$ measures *recall* of baseline words, not precision or F1. Extra unsupported or hallucinated tokens in the candidate answer do **NOT** penalize $R_{\text{token}}$.
2. **Identical String Degeneracy:** When the system outputs the exact target baseline answer string, $\mathbf{e}_{\text{base}} = \mathbf{e}_{\text{rag}}$, yielding $S_{\text{semantic}} = 1.0000$ and $R_{\text{token}} = 1.0000$, resulting in $C = 1.0000$.
3. **Partial Answer Penalization:** If a generated answer provides only 50% of requested facts, $R_{\text{token}} = 0.50$. However, because $S_{\text{semantic}}$ for partially matching medical sentences typically remains $\approx 0.85$, $C = 0.6(0.85) + 0.4(0.50) = 0.71$, which may award passing credit to incomplete answers unless fact-coverage gates are enforced.

## 3. Semantic Similarity Audit

### 3.1 Model Identification
The evaluation framework uses:
- **Model Name:** `all-MiniLM-L6-v2` (`SentenceTransformer`)
- **Embedding Dimensions:** 384
- **Normalization:** Embeddings are L2-normalized prior to cosine similarity computation (`util.cos_sim`).

### 3.2 Explanation for 0.9997 Similarity
The extremely high average semantic similarity ($0.9997$) on the development benchmark is directly caused by **near-total string identity**.
As proven in Section 2, the production generator returns the exact ground-truth sentences verbatim. Cosine similarity between identical text strings is mathematically $1.0000$.

### 3.3 Multilingual Embedding Validity
`all-MiniLM-L6-v2` was trained predominantly on English corpus data. When comparing Hindi (`प्रमेह...`) or Kannada (`ಅಶೋಕದ...`) text against English text, `all-MiniLM-L6-v2` produces unreliable representations.  
However, because both the baseline and the RAG answer were in the **same native script** (e.g. Hindi vs Hindi, Kannada vs Kannada), the identical script strings yielded cosine similarities of $1.0000$. For rigorous cross-lingual semantic evaluation in future work, a multilingual model such as `paraphrase-multilingual-MiniLM-L12-v2` should be deployed.

## 4. Faithfulness Discrepancy Investigation

### 4.1 The Paradox: Correctness $\approx 100\%$ vs Faithfulness $= 89.60\%$
How can Answer Correctness be 99.98% while Faithfulness is 89.60%?
The audit identified two key causes:
1. **Retrieved Context Asymmetry:**
   - In Q26 (*"Which plants share the same Virya as Guduchi?"*), the generated answer hardcodes: `Plants sharing the same Usna Virya as Guduchi include Citraka (Plumbago zeylanica) and Pippali.`
   - The context builder retrieved a list of 15 plants sharing Usna Virya from NetworkX. Because NetworkX node order is non-deterministic, *Citraka* and *Pippali* did not appear in the retrieved top-15 list in that evaluation run.
   - Consequently, while the answer was 100% correct according to the benchmark ground truth, it contained entity claims (*Citraka*, *Pippali*) **not present in the retrieved prompt context**, dropping Faithfulness to **0.4545**!
2. **Multi-Hop Traversal Asymmetry (Q27):**
   - In Q27 (*"Which medicinal plants have disease relationships similar to Ashoka?"*), the answer listed *Guduchi* and *Citraka*.
   - The retrieved context contained only *Ashoka*'s node details. Because *Guduchi* and *Citraka* were absent from the retrieved evidence block, Faithfulness fell to **0.5000**.

This demonstrates that **the Faithfulness metric correctly detected that the hardcoded answer generator was producing facts from outside the retrieved context.**

## 5. Entity Resolution Accuracy Definition & Resolution

### 5.1 The Ambiguity: "96.67% vs 100% strict"
In previous reports, two numbers were presented:
- `96.67%` (58 / 60): Produced by `eval_hybrid_rag.py`.
- `100.00%` (60 / 60): Produced by `generate_failure_analysis.py`.

### 5.2 Root Cause of the Discrepancy
In `eval_hybrid_rag.py`, the check was:
```python
if is_ood or "unknown" in q_type:
    entity_correct = 1.0 if (resolved["type"] == "unknown") else 0.0
```
For Q46 (*XYZHerb*) and Q47 (*ABCDisease*), the resolver returned `resolved["type"] = "unknown_plant"` and `"unknown_disease"`. Because the string `"unknown_plant"` did not equal `"unknown"`, these 2 questions were counted as failures ($58 / 60 = 96.67\%$).

### 5.3 Formal Standard Definition for the Paper
To ensure unambiguous academic rigor, Entity Resolution Accuracy must be formally reported on the **Entity-Applicable Subset**:

$$\text{Entity Resolution Accuracy} = \frac{\text{Correctly Resolved Canonical Entities}}{\text{Total Questions with Ground-Truth Entities}}$$

- **Denominator:** $55$ questions (excluding 3 Out-of-Domain questions and 2 Synthetic Unknown queries).
- **Numerator:** $55$ correctly resolved canonical plants or diseases.
- **Accuracy:** $\frac{55}{55} = \mathbf{100.00\%}$.

If evaluated as a 60-item test suite including correct rejection of non-entities:
- **Denominator:** $60$
- **Numerator:** $60$ (55 resolved + 3 out-of-domain identified + 2 unknown recognized)
- **Accuracy:** $\frac{60}{60} = \mathbf{100.00\%}$.
